# Seat: Dual-Build & Sentinel Reviewer

Verify that Case 2 dual-build packages with `bazel2gn`-convertible targets contain
`## BAZEL2GN SENTINEL - DO NOT EDIT BELOW THIS LINE ##` in BUILD.gn, have zero drift between
BUILD.bazel and the generated BUILD.gn section, migrate all convertible library/code targets
into BUILD.bazel without skipping them via `# @bazel2gn:skip`, and pass the `verify_bazel2gn` step of
`build_verification` without drift.

## Sentinel Completeness, Anti-Skip & Verification Audit
1. **No Target-Level `# @bazel2gn:skip` on Convertible or Reference Libraries & No Duplicate GN Targets Above Sentinel**:
   - Reject (`passed=false`) any `BUILD.bazel` target using a `bazel2gn`-convertible rule (`fx_cc_library`, `cc_library`, `fx_cc_library_headers`, `cc_binary`, `rustc_library`, `rust_library`, `rustc_binary`, `rust_binary`, `rustc_proc_macro`, `rust_proc_macro`, `go_library`, `go_binary`, `py_library`, `py_binary`, `fidl_library`, `zither_fidl_library`, `idk_cc_*`) that is annotated with `# @bazel2gn:skip` (EXCEPT a binary with `tags = ["manual"]` wrapped by `fx_packaged_binary` for an `fx_package`), or any `BUILD.gn` with a sentinel that retains a convertible target above `## BAZEL2GN SENTINEL` (EXCEPT a `testonly = true` `executable` used only by a GN test that the summary says Bazel cannot express yet). bazel2gn never translates tests: in a dual-build `BUILD.bazel`, every test target (`fx_cc_binary(testonly)`, `rustc_test`, `go_test`, `fx_test`, `fx_test_component`, the test `fx_package`/`fx_component_manifest`/`fx_packaged_binary`, `test_suite`, `host_*_test`) and the `with_unit_tests`/`test_deps` attributes of `rustc_*` targets MUST carry `# @bazel2gn:skip`, and the generated section below the sentinel MUST NOT contain `rustc_test`, `go_test`, `with_unit_tests` or `test_deps`; the `bazel_test_suite` exporting the tests belongs above the sentinel.
   - **Device Test Packages**: a `fuchsia_unittest_package`/`fuchsia_test_package` (C++ or Rust) left above the sentinel is a failing finding unless the summary names a real blocker (`test_specs` other than `log_settings`, `test_type` or custom realms, subpackages, `bootfs_test`, Ninja-generated inputs); such a kept GN test depends on a hand-written test executable above the sentinel, never on a bazel2gn-generated `:<name>_test`.
   - **Package-Only `BUILD.bazel` (`fx_package`) Exception**: `bazel2gn` does NOT convert `fx_package`, `fx_component`, `fx_component_manifest`, `fx_packaged_binary`, `fx_cc_binary`, or `resource`. When a package's `BUILD.bazel` only defines `fx_package` (and its component/manifest/binary/resource/`fx_test`/`exports_files` targets) while `BUILD.gn` retains only GN-only targets (`bazel_test_suite`, `group("tests")`, a test Bazel cannot express yet with its `testonly` test `executable`, or a library whose own deps are still GN-only), `BUILD.gn` MUST NOT have `## BAZEL2GN SENTINEL` or `verify_bazel2gn`. Conversely, if the migrated `fuchsia_package`/`fuchsia_package_with_single_component`/`fuchsia_component` was left behind in `BUILD.gn`, or if `//bundles/assembly/bazel_inputs/<pkg>` was not replaced in `//bundles/assembly/BUILD.bazel` and deleted, reject (`passed=false`).
   - Specifically reject skipping standalone reference or bitrot-prevention targets (such as a `static_library` of C++ reference routines depended upon by `group("tests")` in `BUILD.gn`). Require removing `# @bazel2gn:skip` in `BUILD.bazel`, deleting the manual `static_library` / `source_set` above the sentinel in `BUILD.gn`, using `# @bazel2gn:raw_overwrite:[ "<gn_config_1>", ... ]` on the closing `],` of `copts = [...]` when `copts` flags map to GN `configs`, and re-running `fx bazel2gn` so the target is generated below the sentinel.
2. **bazel2gn Sync Verification**:
   - Verify that the generated section below `## BAZEL2GN SENTINEL` matches BUILD.bazel: the `verify_bazel2gn` step of `build_verification` passes. Reject (`passed=false`) on drift.

## Dual-Build Visibility & bazel2gn Audit
3. Prioritize Bazel-correctness over GN-workarounds: reject `":__pkg__"` inside `visibility = [...]` in `BUILD.bazel` even when used to trigger `":*"` generation in `BUILD.gn`. `fx bazel2gn` automatically adds `":*"` in `BUILD.gn` when converting restricted `visibility` lists.
4. **Reject Overly Narrow Sprawling Allowlists on Globally-Used Platform Libraries (`> 15` entries across `>= 6` areas)**:
   - When a shared library or test utility in `BUILD.bazel` is globally used across `>= 6` distinct top-level areas (`per_target_is_globally_used = true` in `find_rdeps`, `> 15` narrow entries / `>= 20` rdep packages), reject any target that replaces `default_visibility = ["//visibility:public"]` with a sprawling 20–50+ entry `visibility = [...]` list of leaf `:__pkg__` packages ("too narrow").
   - Require target-level `visibility = ["//visibility:public"]` (or a concise `<= 15`-entry 2–3 level area rollup) on the target in `BUILD.bazel` and verify `BUILD.gn` is regenerated via `fx bazel2gn` (producing `visibility = [ "*" ]`).
5. Reject overbroad `:__subpackages__` wildcards in `BUILD.bazel` (and their `/*` counterparts in `BUILD.gn`):
   - Reject `"//:__subpackages__"`, `"//src:__subpackages__"`, `"//sdk:__subpackages__"`, and multi-domain library/test umbrellas (`"//src/lib:__subpackages__"`, `"//sdk/lib:__subpackages__"`).
   - On non-global targets (`<= 15` narrow entries), reject cross-area depth-2 wildcards (`"//src/<area>:__subpackages__"`, such as `"//src/storage:__subpackages__"`, `"//src/connectivity:__subpackages__"`, or `"//src/starnix:__subpackages__"` on targets defined outside `//src/<area>`). Require narrowing to exact `:__pkg__` packages or depth >= 3 component subtrees (`//src/<area>/<subcomponent>:__subpackages__`) matching `per_target_recommended_visibility` from `find_rdeps`, and verify `BUILD.gn` is regenerated via `fx bazel2gn`.
   - Reject visibility entries pointing to packages that only reference GN-only targets above the sentinel (`:tests`, `:benchmarks`, `:verify_bazel2gn`).
   - Reject any internal vendor subpath in `visibility = [...]`; require `"//vendor/google:__subpackages__"` in `BUILD.bazel` (`"//vendor/google/*"` in `BUILD.gn`) whenever exposing a target to the vendor tree.
6. **Build-Only Scope & Minimality**: A dual-build migration may only change `BUILD.bazel`, the bazel2gn-generated `BUILD.gn`, and build registration lists (`*.gni`/`*.bzl`), plus a newly added `.cml` used as `manifest` by the `fx_component_manifest` of a migrated `fx_test_component` and an `exports_files` of the test runner shards it includes (in `src/sys/test_runners/**/BUILD.bazel` or `sdk/lib/sys/testing/BUILD.bazel`, created if missing). Reject any modification to source or data files in the change, regardless of how small, and reject redundant default attributes (`crate_name == name`, `version = "0.1.0"`, default `crate_root`) in `BUILD.bazel`. Inspect `git diff --stat $PLANTER_CHANGE_BASE` plus untracked files (never `git show HEAD`: when `$PLANTER_CHANGE_BASE` is `HEAD`, the HEAD commit is unrelated upstream history); a one-line lint-silencing edit (e.g. removed `.clone()` in a `#[cfg(test)]` module after switching GN `configs` to Bazel `lint_config`) is a failing finding with file:line.
7. **`lint_config` Label Parity, No Wrapper Pairs & CQ Reachability**: bazel2gn copies each `lint_config` label verbatim into the generated section. Verify the label's package BUILD.gn defines `config("<name>")` next to the Bazel `rust_lint_config` of the same name. Reject (passed=false) labels that resolve only through a wrapper added by this change (a new Bazel `alias()` paired with a GN `config()` that just forwards to another config) and require the defining target's label instead; wrapper labels that existed before the change are acceptable. Also verify that all migrated tests still reach `tests.json`: GN test targets/packages wired into `group("tests")`, and every Bazel `fx_test`/host test listed, directly or via a Bazel `test_suite`, in a GN `bazel_test_suite` (`target_tests` for `fx_test`, `host_tests` for host tests) that `group("tests")` lists. A Bazel test that is only defined (or only runnable with `fx bazel test`) is dropped from CQ: reject it.
8. **Above-Sentinel Dependency Forwarding Group Shape**: The only hand-written dependency-routing target allowed above the sentinel is the forwarding group for a Rust `public_deps` edge whose target has `public_configs` (bazel2gn emits Rust deps as private): a `group` with `visibility = [ ":*" ]`, `public_deps` = exactly the original label, `all_dependent_configs` = exactly that target's `public_configs`, a comment saying why, and referenced from BUILD.bazel with `# @bazel2gn:path_overwrite::<group>`. Reject any other routing group or config added by the change (extra configs or deps, wider visibility, `rustflags`/`ldflags`/`libs` added by hand).
