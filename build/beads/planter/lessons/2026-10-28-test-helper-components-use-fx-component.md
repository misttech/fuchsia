# Helper components packaged next to a test use `fx_component(testonly = True)`

- **Learned from:** human review of CL 1926390
  (`//src/security/tests/pkg_test/{dns_resolver,paver,reboot}`)
- **Date:** 2026-10-28
- **Changed:** `checks/gn_target_type_parity.sh`, `checks/migration_sanity.sh`,
  `prompts/coder.md`

## Root cause

The three mock services in `//src/security/tests/pkg_test` (DNS resolver, paver,
reboot) were GN `fuchsia_test_component`s without `test_type`, listed in the
`deps` of a `fuchsia_test_package` rather than its `test_components`. The coder
handled them two different ways in the same change:

- `dns_resolver` used `fx_test_component`. That marks the component `is_test`,
  which `fx_package` only accepts in `test_components`, and bazel2gn never
  translates it, so the hand-written GN target stayed above the sentinel and the
  Bazel target had no users and no `visibility`.
- `paver` and `reboot` used `fx_component(testonly = True)` but added
  `# @bazel2gn:skip` ("bazel2gn does not translate fx_component to
  fuchsia_test_component") and kept the GN target above the sentinel, again
  without `visibility`.

Both came from `gn_target_type_parity.sh`: letting bazel2gn emit
`fuchsia_component` for a former `fuchsia_test_component` raised
`gn_target_type_changed`. But `//build/components/fuchsia_test_component.gni`
only adds `testonly = true` and, when `test_type` is set, test realm metadata to
`fuchsia_component`. Without `test_type` the two are the same GN target.

## Remediation

1. `gn_target_type_parity.sh` accepts `fuchsia_test_component` ->
   `fuchsia_component` when the old target had no `test_type` and the generated
   one is `testonly = true`.
2. `migration_sanity.sh` reports a new `fx_test_component` that no `fx_package`
   lists in `test_components` (`test_component_not_test_root`), and a skipped
   `fx_component` whose GN copy above the sentinel is a `fuchsia_test_component`
   without `test_type` (`skipped_test_helper_component`).
3. `prompts/coder.md` says helper components are `fx_component(testonly = True)`
   with `visibility` from `find_rdeps`, generated by bazel2gn.
