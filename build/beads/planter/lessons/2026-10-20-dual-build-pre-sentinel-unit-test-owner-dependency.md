# Dual build pre sentinel unit test owner dependency resolution

- **Learned from:** cq failure on CL I7aea904d7b1480880c8812bc19eeafa12b95d500, patchset 1 (task `pkg-cache-config`)
- **Date:** 2026-10-20
- **Changed:** `checks/migration_sanity.sh`

## Root cause

In checks/migration_sanity.sh, inspect_gn_target_deps() only looked up local
dependency labels by exact target name in pre_targets, ignoring implicit
:<owner>_test unit-test targets generated by with_unit_tests = true on a
pre-sentinel rustc_binary or rustc_library target and causing
check_unmigrated_kept_pkg_test_targets() to falsely report that a kept GN test
component's dependencies were Bazel-buildable.

## Why not a one-off fix

Hardcoding an exception for a single package or component name would leave any
other dual-build package whose kept GN test component depends on an implicit
:<owner>_test target of a GN-blocked rustc_binary or rustc_library vulnerable to
the same false-positive unmigrated_dual_build_test_component error.
